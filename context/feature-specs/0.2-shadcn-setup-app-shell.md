# 0.2 shadcn/ui Setup and Responsive App Shell

**Phase:** 0, Foundation
**Status:** Complete
**Depends on:** Unit 0.1 (theme tokens, fonts and metadata)

## Goal

Install shadcn/ui on top of the unit 0.1 tokens, and build the app shell every signed-in page will
use: the sidebar, a compact top bar on phones, and a page header with a breadcrumb and title. When
this unit is done, all nine navigation items open a placeholder page inside the shell, and the shell
works at phone, tablet and desktop widths in light and dark mode.

## Scope

**In scope**

- `shadcn init`, with its generated files and dependencies
- `lucide-react` for icons, plus `clsx` and `tailwind-merge` for the `cn()` helper, all installed by the
  shadcn CLI
- shadcn's semantic variables (such as `--background`, `--primary` and `--sidebar`) mapped to the
  FinTrack tokens, with dark mode still following the system setting
- The shadcn components the shell needs: `sidebar` (which brings `button`, `separator`, `sheet`,
  `tooltip`, `input`, `skeleton` and the `use-mobile` hook) and `breadcrumb`
- The `app/(app)` route group with a shared shell layout
- Sidebar with the logo, the main navigation and the "ACCOUNT" group
- Phone top bar with a menu button that opens the sidebar as a slide-over
- Page header with breadcrumb and title
- Placeholder pages for the nine navigation items, and `/` redirecting to `/dashboard`
- Doc updates in `ui-context.md`, `code-standards.md` and `progress-tracker.md`

**Out of scope**

- Sign-in, the user menu, "Hi, <name>", the avatar and sign out (Phase 1)
- Route protection and `proxy.ts` (Phase 1)
- The notifications bell (Phase 6)
- The sidebar help card (Phase 16)
- A manual light or dark switch (Phase 14)
- Remembering the sidebar's open state in a cookie
- Real page content, such as dashboard figures or tables
- Any shadcn component the shell doesn't use. Later units add their own.

## Implementation

### 1. Initialize shadcn/ui

1. Check the current shadcn docs for Next.js and Tailwind v4 before running anything, since the CLI's
   prompts and defaults change between versions.
2. Run `npx shadcn@latest init` with these choices:
   - Component base: Radix (the Sidebar docs are written for it)
   - Style: the CLI's default
   - Base color: neutral (step 2 replaces its values anyway)
   - CSS variables: yes
   - Icon library: Lucide
   - Aliases: the defaults (`@/components`, `@/components/ui`, `@/lib`, `@/lib/utils`, `@/hooks`)
3. Run `npx shadcn@latest add sidebar breadcrumb`.
4. Confirm `lucide-react`, `clsx` and `tailwind-merge` are in `dependencies`. If `lucide-react` is
   missing, run `npm install lucide-react`. This is the one approved install outside the shadcn CLI.
5. Record the shadcn CLI version in this spec's Notes.

`init` also creates `lib/utils.ts` with the `cn()` helper, which joins class names and resolves
conflicting Tailwind classes. Every generated component imports it, so it is required. Treat it as a
generated file. Later shared helpers go in their own `lib/` modules.

The project loads Tailwind through `@tailwindcss/turbopack` rather than PostCSS. If `init` can't detect
Tailwind, stop and report. Do not add a PostCSS config or change `next.config.ts` without approval.

### 2. Adapt `app/globals.css`

`init` rewrites this file. Review the full diff, then make it match this layout:

1. **Imports:** keep `@import "tailwindcss";` first, then any imports `init` added, such as
   `tw-animate-css` or `shadcn/tailwind.css`.
2. **Remove the class-based dark variant:** delete `@custom-variant dark (&:is(.dark *));`, so `dark:`
   keeps following `prefers-color-scheme`, as decided in unit 0.1.
3. **Remove shadcn's color values:** delete its `.dark { ... }` block and the `oklch(...)` values it put
   in `:root`.
4. **Keep the FinTrack token blocks unchanged:** the light `:root` block and the dark media block from
   unit 0.1.
5. **Add one shadcn mapping block** after them. Because each line points at a FinTrack token, dark mode
   follows automatically, and no dark copy is needed:

   | shadcn variable                 | FinTrack token           |
   | ------------------------------- | ------------------------ |
   | `--background`                  | `--bg-base`              |
   | `--foreground`                  | `--text-primary`         |
   | `--card`, `--popover`           | `--bg-surface`           |
   | `--card-foreground`, `--popover-foreground` | `--text-primary` |
   | `--primary`                     | `--action-primary`       |
   | `--primary-foreground`          | `--action-contrast`      |
   | `--secondary`, `--muted`, `--accent` | `--bg-muted`        |
   | `--secondary-foreground`, `--accent-foreground` | `--text-primary` |
   | `--muted-foreground`            | `--text-muted`           |
   | `--destructive`                 | `--state-error`          |
   | `--border`, `--input`           | `--border-default`       |
   | `--ring`                        | `--focus-ring`           |
   | `--chart-1`                     | `--chart-primary`        |
   | `--chart-2`                     | `--chart-secondary`      |
   | `--sidebar`                     | `--bg-surface`           |
   | `--sidebar-foreground`          | `--text-primary`         |
   | `--sidebar-primary`             | `--bg-inverse`           |
   | `--sidebar-primary-foreground`  | `--text-on-inverse`      |
   | `--sidebar-accent`              | `--bg-muted`             |
   | `--sidebar-accent-foreground`   | `--text-primary`         |
   | `--sidebar-border`              | `--border-default`       |
   | `--sidebar-ring`                | `--focus-ring`           |

   Drop `--chart-3` to `--chart-5`. Phase 5 decides the extra chart colors. If `init` adds a shadcn
   variable not listed here, map it to the closest token and add it to this table.

6. **Radius:** keep `--radius: 0.5rem` in case a generated component reads it, but delete the
   `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl` (and any larger) lines from `@theme inline`.
   Those override Tailwind's built-in radius classes, which `ui-context.md` relies on.
7. **`@theme inline`:** keep the unit 0.1 mappings and the font mappings, and keep shadcn's
   `--color-background: var(--background)` style mappings, so generated classes such as `bg-background`
   and `bg-sidebar` work.
8. **Base layer:** use one `@layer base`. Keep the unit 0.1 rules for `body`, `:focus-visible` and
   reduced motion. From shadcn's base rules, keep the default border color (`border-border` on `*`), and
   drop its `body` rule and `outline-ring/50`, which unit 0.1's rules already cover.

Hex values must still appear only in the two FinTrack token blocks.

### 4. Sidebar

`components/app-shell/app-sidebar.tsx` renders shadcn's `Sidebar` (default `offcanvas` collapsible,
which also gives the phone slide-over):

- **Header:** the "FinTrack" wordmark in `font-semibold`, linking to `/dashboard`, then a
  `SidebarSeparator` as the faint divider.
- **Content:** a `SidebarGroup` for the main navigation, then a `SidebarGroup` whose
  `SidebarGroupLabel` reads "ACCOUNT" (`uppercase`, at least 12px), for Profile and Settings.
- **No right border:** the sidebar is separated from content by whitespace. Remove shadcn's border
  through `className` on `<Sidebar>` (with Tailwind's `!` modifier if needed), not by editing
  `components/ui/sidebar.tsx`.
- **Width:** about `w-60`. Set `--sidebar-width: 15rem` through the `style` prop on `SidebarProvider`.

`components/app-shell/sidebar-nav.tsx` is the only new client component. It takes one list of nav items
and renders `SidebarMenu` items:

- Each item is a `SidebarMenuButton` with `asChild` around a Next.js `Link`, at least `h-11`,
  `rounded-2xl` and `font-medium`, with the icon tile and the text label.
- **Active state:** use `usePathname()`. An item is active when the path equals its `href` or starts
  with `href + "/"`. Set `isActive` and `aria-current="page"`.
- **Active style:** `bg-inverse text-on-inverse` pill. The icon tile is `bg-surface` with a `text-ink`
  icon.
- **Inactive style:** `text-ink`, with a hover of `bg-fill`. The icon tile is `bg-surface` with
  `shadow-sm` in light mode, and a `border-line` border with no shadow in dark mode.
- **Icon tile:** `size-8 rounded-lg`, icon `size-5`, `aria-hidden`.
- **Phones:** after a link is clicked, call `setOpenMobile(false)` from `useSidebar()`, so the
  slide-over closes.
- **Motion:** color transitions of 150 to 250ms.
- **Classes:** combine the shared, active and inactive classes with `cn()` from `@/lib/utils`, so they
  cleanly override `SidebarMenuButton`'s defaults, such as its height.

The active tile icon uses `text-ink` rather than slate, because the slate token is too dark against the
tile in dark mode. Step 10 records this in `ui-context.md`.

### 5. Phone top bar and shell layout

`components/app-shell/mobile-top-bar.tsx` is shown only below the `md` breakpoint (`md:hidden`). It
holds a `SidebarTrigger` resized to at least 44px (`size-11`) with an accessible name, and the
"FinTrack" wordmark. It sticks to the top of the page.

`app/(app)/layout.tsx`:

```tsx
<SidebarProvider defaultOpen style={{ "--sidebar-width": "15rem" } as React.CSSProperties}>
  <a href="#main" className="sr-only focus:not-sr-only ...">Skip to content</a>
  <AppSidebar />
  <SidebarInset>
    <MobileTopBar />
    <main id="main" className="mx-auto w-full max-w-6xl px-4 py-6 md:px-6 lg:px-8">
      {children}
    </main>
  </SidebarInset>
</SidebarProvider>
```

- Do not read the sidebar cookie with `cookies()`. That would make every page dynamic under
  `cacheComponents`, and remembering the open state is out of scope.
- On desktop the sidebar stays open, and no trigger is shown. shadcn's Ctrl/Cmd+B shortcut can still
  hide it, and pressing it again brings it back. That is acceptable for now.
- The skip link becomes visible on focus and moves focus past the navigation.

## Decisions

- **shadcn variables point at FinTrack tokens:** one mapping block, written once, so dark mode follows
  the unit 0.1 media query with no second copy, and there's still one source of truth for color.
- **Tailwind's built-in radius scale:** shadcn's `--radius-*` overrides would quietly change
  `rounded-md`, `rounded-lg` and `rounded-xl` across the app, so they're removed.
- **`/dashboard` route, with `/` redirecting:** matches the "Home / Dashboard" breadcrumb, and leaves `/`
  free for Phase 1's signed-out behavior.
- **Placeholder pages for every nav item:** so no navigation link leads to a 404, and so active states,
  titles and the phone menu can be checked now.
- **Text wordmark as the logo:** there is no logo file yet. This avoids adding a non-Lucide graphic.
- **No sidebar cookie:** keeps pages static under `cacheComponents`.

## Notes

- Playwright isn't set up until a later Phase 0 unit. Browser checks will use `playwright-core` from the
  scratchpad against the installed Chrome, as in unit 0.1.
- **Focus rings on generated components:** shadcn's buttons and inputs use a 3px ring at 50% opacity
  (`ring-ring/50`), not the 2px ring with a 2px offset that `ui-context.md` asks for, and at 50% the
  light-mode ring may fall below 3:1 contrast. The shell's nav items and menu button are checked here.
  The first unit that uses shadcn buttons or inputs in a form (Phase 1) must restyle them through
  `className` and check the contrast.
- **Destructive buttons in dark mode:** shadcn puts white text on `--destructive`, and white on the dark
  error color (`#F87171`) fails 4.5:1. The first unit with a destructive button must handle this.

## Implementation Notes (2026-11-12)

- **shadcn CLI 4.23.0**, run as `shadcn init -t next -b radix -p nova`. This gave the `radix-nova` style,
  `neutral` base color, CSS variables and Lucide. `nova` is the CLI's default style.
- **Dependencies the CLI added:** `class-variance-authority`, `cn`, `lucide-react`, `radix-ui`, `shadcn`
  (for `@import "shadcn/tailwind.css"`) and `tw-animate-css`. Nothing was installed by hand.
- **`cn` instead of `clsx` + `tailwind-merge`:** this CLI version installs its own `cn` package (from the
  shadcn-ui organization), which replaces both. `lib/utils.ts` re-exports it, and generated components
  import it directly. A check confirmed it merges FinTrack's custom names correctly (`text-sm` +
  `text-ink` keeps both; `h-8` + `h-11` gives `h-11`).
- **`init` broke the font mapping:** its "Updating fonts" step changed `--font-sans` to reference itself.
  The mapping to `--font-geist-sans` was restored, and `--font-heading`, which generated components use,
  was mapped to Geist as well. `app/layout.tsx` was not changed.
- **Lint override:** only `react-hooks/set-state-in-effect` was turned off, only for `components/ui/**`
  and `hooks/use-mobile.ts`. It flagged `setIsMobile` inside an effect in `use-mobile.ts`.
- **No nested `<main>`:** `SidebarInset` already renders `<main>`, so the skip-link target is
  `<div id="main" tabIndex={-1}>` inside it, rather than a second `<main>` as in the step 5 sketch.
- **Nav lists are imported in the client component:** Lucide icons are components and can't be passed
  from a Server Component, so `SidebarNav` takes `group="main" | "account"` instead of an item list.
- **Active pill overrides:** the generated button styles hover with higher specificity than its
  `data-active` style, so the active item also sets `hover:` and `active:` to the slate pill.
- **Separator fix:** the generated separator's `data-horizontal:w-full` beats `SidebarSeparator`'s
  `w-auto`, so it overflowed the sidebar by 8px. Fixed with `className="data-horizontal:w-auto"`.
- **`TooltipProvider` not added:** the CLI suggests it, but the shell uses no tooltips. Add it with the
  first unit that does.
- **Browser checks** ran with `playwright-core` and the installed Chrome against the owner's running dev
  server on port 3000, at 1440, 1024, 768 and 375px, in light and dark mode, with reduced motion
  emulated. All checks passed, including no console or hydration errors. Nav focus is a 2px ring with a
  2px offset in `--focus-ring`.
