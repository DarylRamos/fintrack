# 0.1 Theme Tokens, Fonts and Metadata

**Phase:** 0, Foundation
**Status:** Complete
**Depends on:** Nothing. This is the first unit.

## Goal

Set up FinTrack's visual foundation, so every later screen can use one shared set of design tokens.
When this unit is done, the app has its light and dark colors, Geist as its font and correct page
metadata, and it follows the system's light or dark setting.

## Scope

**In scope**

- All color tokens from `context/ui-context.md`, for light and dark modes
- Tailwind utility names for those tokens
- Geist font mapping
- Base page styles: background, text, focus ring and reduced motion
- FinTrack page title and description
- A small wording update in `context/ui-context.md`

**Out of scope**

- shadcn/ui and its semantic tokens (unit 0.2)
- The sidebar, app shell and any other screens (unit 0.2)
- A manual light or dark switch (Phase 14)
- New dependencies, including `next-themes`
- Radius, shadow or spacing tokens, because Tailwind's built-in classes already cover them

| ------------------------ | --------------------------------------------------- |

## Implementation

### 1. Define the color tokens

In `app/globals.css`, below `@import "tailwindcss";`:

1. Add all 17 tokens to `:root`, using the **Light** values from the Colors table in
   `context/ui-context.md`.
2. Add the same 17 tokens inside `@media (prefers-color-scheme: dark) { :root { ... } }`, using the
   **Dark** values.
3. Set `color-scheme: light` in `:root` and `color-scheme: dark` in the dark block, so native controls
   and scrollbars match.

Copy values from the table exactly. Do not add or rename any `--` token.

### 2. Map the tokens to Tailwind utilities

Add an `@theme inline` block, so classes such as `bg-surface` and `text-ink` work:

| Tailwind variable           | Token                     | Example class          |
| --------------------------- | ------------------------- | ---------------------- |
| `--color-page`              | `--bg-base`               | `bg-page`              |
| `--color-surface`           | `--bg-surface`            | `bg-surface`           |
| `--color-fill`              | `--bg-muted`              | `bg-fill`              |
| `--color-inverse`           | `--bg-inverse`            | `bg-inverse`           |
| `--color-ink`               | `--text-primary`          | `text-ink`             |
| `--color-ink-muted`         | `--text-muted`            | `text-ink-muted`       |
| `--color-on-inverse`        | `--text-on-inverse`       | `text-on-inverse`      |
| `--color-on-inverse-muted`  | `--text-on-inverse-muted` | `text-on-inverse-muted`|
| `--color-action`            | `--action-primary`        | `bg-action`            |
| `--color-on-action`         | `--action-contrast`       | `text-on-action`       |
| `--color-line`              | `--border-default`        | `border-line`          |
| `--color-focus`             | `--focus-ring`            | `outline-focus`        |
| `--color-chart-primary`     | `--chart-primary`         | `stroke-chart-primary` |
| `--color-chart-secondary`   | `--chart-secondary`       | `stroke-chart-secondary` |
| `--color-error`             | `--state-error`           | `text-error`           |
| `--color-warning`           | `--state-warning`         | `text-warning`         |
| `--color-success`           | `--state-success`         | `text-success`         |

These names deliberately avoid `base` (which would clash with the `text-base` font size) and shadcn's
own names (`primary`, `muted`, `accent`, `border`, `ring`), which unit 0.2 adds.

### 3. Map the fonts

In the same `@theme inline` block, add:

```css
--font-sans: var(--font-geist-sans);
--font-mono: var(--font-geist-mono);
```

`app/layout.tsx` already loads both fonts, so it needs no font changes.

### 4. Add base styles

Add these to `@layer base` in `app/globals.css`:

- `body`: `--bg-base` background, `--text-primary` text and the sans font
- `:focus-visible`: a 2px solid `--focus-ring` outline with a 2px offset
- `@media (prefers-reduced-motion: reduce)`: reduce animation and transition durations to almost nothing

### 5. Update the metadata

In `app/layout.tsx`, replace the starter metadata:

```ts
export const metadata: Metadata = {
  title: {
    default: "FinTrack",
    template: "%s | FinTrack",
  },
  description: "Track your income, expenses, budgets, goals, investments and debts in one place.",
};
```

Keep the existing `lang`, font variables and layout classes, and add `bg-page text-ink` to `<body>`.

### 6. Use the tokens on the placeholder page

In `app/page.tsx`, add `text-ink` to the "FinTrack" element, so the page shows the tokens working. Do not
build a real home page. That arrives with later units.

### 7. Update `context/ui-context.md`

- In the Colors section, replace "with a complete set for both `:root` and `.dark`" with the approach in
  the decision below.
- Add the Tailwind utility names from step 2.

## Decision: System Dark Mode Without a Library

Dark mode uses the CSS `prefers-color-scheme` media query, which is also Tailwind v4's default `dark:`
behavior.

- **Why:** the app only needs to follow the system until Phase 14. This approach needs no JavaScript or
  new dependency, and it avoids hydration warnings and a flash of the wrong theme on load.
- **Change from `ui-context.md`:** the current wording mentions a `.dark` class, so step 7 updates it.
- **Later:** Phase 14 adds a `.dark` class and a theme switch for the manual setting.
- **Unit 0.2 must check:** `shadcn init` may add its own `.dark` block and dark variant. They need to be
  adapted to this approach so that `dark:` classes and tokens stay in step.

## Rules to Follow

- Follow `context/ui-context.md` for values, and `context/code-standards.md` for styling rules.
- Keep raw hex values only in the token blocks in `app/globals.css`.
- Check `node_modules/next/dist/docs/` before relying on any Next.js API.
- Do not change `next.config.ts` in this unit.
